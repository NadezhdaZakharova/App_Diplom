## 1. Назначение и концепция

`App_Diplom` — Android-приложение для организации тренировок в двух ролях:

- **Ученик** — свой план и план от тренера, шаги, награды и геймификация.
- **Тренер** — сбор плана «для ученика» и передача в виде **JSON**.

Подход **offline-first**:

- хранение — локальная БД **Room**;
- UI — **Jetpack Compose**;
- данные — **Flow / StateFlow**;
- геймификация пересчитывается на устройстве, в том числе **WorkManager**.

## 2. Функционал

### 2.1 Роли и режимы

- Выбор режима **ученик / тренер** при старте и переключение с верхней панели.
- У ученика вкладки **«Тренировка»** и **«Награды»**; у тренера акцент на плане (вкладка наград скрыта).

### 2.2 Банк упражнений

- Поля: название, описание, длительность по умолчанию (секунды).
- У предустановленных записей в БД есть **`titleKey`** для локализации названий (RU/EN); свои упражнения показываются текстом из БД.
- Добавление и редактирование с экрана тренировок.

### 2.3 Экран тренировок (ученик)

- Две крупные зоны: **«Самостоятельная»** и **«От тренера»** — работают как **аккордеон**: открыта не больше одной; повторное нажатие по активной зоне **сворачивает** её (можно свернуть обе).
- **Цель по шагам на день** — отдельная карточка: заголовок сворачивает/разворачивает поле ввода и кнопку; после успешного сохранения кнопка на короткое время показывает **«Сохранено»**.

### 2.4 Тренировка тренера

- Сбор плана из банка, порядок и длительности.
- **Экспорт JSON** (`TrainerWorkoutJsonStore`): предпросмотр, копирование, отправка через **ACTION_SEND**.
- В JSON может передаваться **`titleKey`** для локализуемых названий у ученика.

### 2.5 Импорт тренировки учеником

- Ввод JSON в поле или приём через **«Поделиться»** (`MainActivity`, `text/plain`).
- Валидация, сохранение плана на сегодня; обратная связь через snackbar.

### 2.6 Сохранение упражнений из плана тренера

- В секции «От тренера» — **«Сохранить в мой банк»** для выбранных позиций (с кратким подтверждением на кнопке).

### 2.7 Сессия тренировки

- Текущее упражнение, таймер, прогресс, **пауза** / продолжение.
- Выход с подтверждением и сбросом прогресса сессии.
- По завершении (ученик) — запись сессии и событий для **наград**.

### 2.8 Шаги, цель и «сегодня»

- Шаги через **StepCounterManager** при разрешении **ACTIVITY_RECOGNITION** (начисление только с сенсора).
- Дневная цель по шагам настраивается учеником (см. п. 2.3).
- «Сегодня» в репозитории активности корректно обновляется при **смене календарного дня** (в т.ч. без обязательной записи в БД).

### 2.9 Награды, статистика и геймификация

- Вкладка **«Награды»**: карточки (упражнение недели, марафон, месяц, серия, первая неделя, разнообразие, тренировка от тренера), блок **активности**: **шаги и дистанция только за сегодня**; ниже — список дней с прогрессом к цели.
- **Серия «тренировочных дней»** в наградах: день засчитывается при **завершённой сессии** или при **шагах ≥ 1,5× дневной цели** (согласовано с бонусом XP в профиле).
- При шагах ≥ 1,5× цели — предложение **конвертировать шаги в опыт тренировки**: не диалог поверх экрана, а **встроенная карточка в списке**, сразу **над** заголовком **«Активность»**; согласие записывает сессию типа **STEPS** за сегодня, отказ скрывает предложение до следующего дня (флаг в настройках).
- При достижении **дневной цели по шагам** — зелёный баннер над блоком активности.
- **Прогресс по дням** в списке активности считается от **текущей** цели по шагам (`dailyGoal`), а не от фиксированного числа.
- **Уведомления** (канал «Шаги и цели»): достижение дневной цели; бонус **1,5×** — отдельно; не чаще одного раза каждого типа за календарный день. Тексты канала и уведомлений лежат **только** в ресурсах модуля **`:data`**.

### 2.10 Геймификация профиля

- XP, уровень, серия и множитель завязаны на те же **1,5× цели по шагам**, что и бонус за день и серия в наградах.
- Достижения, weekly challenge, фоновый пересчёт (**DailyRecalculateWorker**).

## 3. Архитектура

Слоистая схема **MVVM**.

### 3.1 UI (`ui`)

- Compose-экраны и компоненты.
- **MainViewModel** — центр действий: только **use case**; для чтения состояния — **`ObserveCoreMainUiInputsUseCase`**.
- **MainUiState** — агрегированное состояние.
- Навигация: **NavigationSuiteScaffold** и локальное состояние, без **NavHost**.

### 3.2 Модуль `:domain`

- Модели, контракты репозиториев, **GamificationEngine**, **StudentRewardsCalculator**, **StepStreakThresholds**, **ExerciseTitleKeys**.
- Use case: шаги и цель (**AddSteps**, **SetDailyGoal**), старт (**BootstrapGame**), импорт JSON (**ImportWorkout**, **ApplyShareImportAsStudent**), подготовка хранилища тренировок, режим пользователя, план/банк/экспорт/конвертация шагов, завершение сессии, **`ObserveCoreMainUiInputsUseCase`** — см. **`PROJECT_STRUCTURE.md`**.
- **StepMilestoneNotifier** — контракт; реализация в модуле **`:data`**.

### 3.3 Модуль `:data` (Android Library)

- **Room** (`DiplomDatabase`, миграции, DAO, entities; схемы в `data/schemas`).
- **ActivityRepositoryImpl**, **GamificationRepositoryImpl**, **TrainingRepositoryImpl**.
- JSON: **TrainerWorkoutJsonStore**, **TrainerWorkoutPlannedSecondsParser**.
- **AndroidStepMilestoneNotifier** — реализация **StepMilestoneNotifier** (строки уведомлений в `data/src/main/res/`).
- Hilt: **DatabaseModule**, **RepositoryModule**, **StepMilestoneNotifierModule**.
- Unit-тесты кода этого модуля (импорт JSON, парсер длительностей) — в **`data/src/test`**, рядом с реализацией.

### 3.4 Модуль `:app` (приложение)

- **MainActivity** — share-intent, шагомер → ViewModel.
- **DiplomApplication**, **BootstrapGameUseCaseEntryPoint** — Hilt и доступ к **BootstrapGameUseCase** из **Worker**; первичный bootstrap игры — из **MainViewModel**.
- **DailyWorkScheduler**, **DailyRecalculateWorker**.

## 4. Технологический стек

| Область | Технологии |
|--------|------------|
| Язык / платформа | Kotlin; модули **`:domain`** (JVM), **`:data`** (Android Library), **`:app`** (см. `*/build.gradle.kts`) |
| UI | Jetpack Compose, Material 3, Navigation Suite |
| Архитектура | MVVM, Coroutines, Flow / StateFlow |
| Хранение | Room (KSP), `org.json` для обмена тренировками |

| Совместимость API | Core library **desugaring** (`java.time` на minSdk 24) |
| Тесты | JUnit, AndroidX Test, Compose UI Test; unit **`:domain`** / **`:data`**; instrumented и smoke — **`:app`** (`androidTest`) |

## 5. Границы и ограничения

- Данные **только локально**; облака и **Retrofit** в проекте нет.
- Уведомления зависят от системных настроек и **POST_NOTIFICATIONS** (API 33+).
- Детальная карта файлов и зависимостей между слоями — **`PROJECT_STRUCTURE.md`**.
- Оформление репозитория (переводы строк Git, **`.gitattributes`**) — в **`PROJECT_STRUCTURE.md`**, раздел 5.

## 6. Сильные стороны версии

- Чёткое разделение **ui / domain / data**, тестируемое ядро геймификации и наград.
- Сценарий **тренер → JSON → ученик**, в том числе через **«Поделиться»**.
- Современный стек: Compose, Hilt, Room, Flow.
- Локализация UI и предустановленных названий упражнений (RU/EN).
- Осознанные миграции Room без destructive fallback в релизной конфигурации.
- UX наград и тренировок согласован с дневной целью по шагам (прогресс, баннеры, конвертация, уведомления).
- Тесты и строки уведомлений без дублирования между модулями: см. п. 3.3 и **`PROJECT_STRUCTURE.md`** (раздел 5).
